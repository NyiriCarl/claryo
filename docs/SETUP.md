# Setup and deployment

## 1. Requirements

- Node.js 20+ and pnpm (or npm)
- [Deno 2](https://docs.deno.com/runtime/getting_started/installation/) for the
  local API and the server type check
- A Supabase project for real accounts and cloud sync (optional for local work)
- An Anthropic API key for live AI (optional; without it you get demo mode)

## 2. Run locally (no cloud services needed)

```bash
pnpm install
npm run dev:api
```

`server/dev.ts` runs the same API as the edge function, with a JSON file
(`.data/dev-kv.json`) instead of the database. `npm run dev:api` sets
`DEV_AUTH=true`, which enables a test-only sign-in: any email, no password,
no emails sent. Never set `DEV_AUTH` on a deployed server.

In a second terminal:

```bash
VITE_API_URL=http://localhost:8787/make-server-b327929d \
VITE_AUTH_PROVIDER=dev \
npm run dev
```

Open the printed URL and use your browser's device toolbar at 360–430px wide.

To try live AI locally, start the API with your key:

```bash
ANTHROPIC_API_KEY=sk-ant-... npm run dev:api
```

## 3. Configuration

All values are listed with comments in [`.env.example`](../.env.example).
Copy it to `.env.local` for the web app. The rule of thumb:

- `VITE_*` values are compiled into the browser bundle. Only public values go
  there (the Supabase URL and **anon** key are public by design).
- Everything else is a **server secret**: set it with `supabase secrets set`
  (deployed) or in your shell (local). The Anthropic key and the Supabase
  service-role key must never appear in a `VITE_*` variable.

### Renaming the product

Edit `src/brand.config.ts` (name, short name, tagline, colours, logo), or set
`VITE_BRAND_NAME` / `VITE_BRAND_SHORT_NAME` at build time. The tab title,
install manifest and icon are generated from the same config. Saved data uses
a brand-independent storage prefix, so renaming does not lose anyone's
projects.

## 4. Deploy

### Supabase (API, accounts, storage)

The project already points at Supabase project `jufdbpatfmadpwbbarqt` via
`utils/supabase/info.tsx` (generated by Figma Make). To deploy the API:

```bash
supabase login
supabase link --project-ref <your-project-ref>
supabase secrets set ANTHROPIC_API_KEY=sk-ant-... RATE_LIMIT_SALT=$(openssl rand -hex 16) \
  ALLOWED_ORIGINS=https://your-domain.example
supabase functions deploy make-server-b327929d
```

The function stores data in the `kv_store_b327929d` table that Figma Make
created. If you use a fresh Supabase project, create it first:

```sql
create table kv_store_b327929d (key text not null primary key, value jsonb not null);
alter table kv_store_b327929d enable row level security;  -- no policies: only the service role can access it
```

In the Supabase dashboard, under Authentication:

- **URL configuration:** set the Site URL to your web address and add
  `https://your-domain.example/auth/callback` to the redirect URLs.
- **Email:** keep "Confirm email" on. Set up a custom SMTP sender before
  launch; Supabase's built-in sender is heavily rate-limited.
- **Google (optional):** enable the Google provider with your OAuth client,
  then build the web app with `VITE_GOOGLE_SIGN_IN=true`.

### Web app

`npm run build` writes a static site to `dist/`. Host it on any static host
(Figma Make's publish, Vercel, Netlify, Cloudflare Pages). Configure the host
to serve `index.html` for unknown paths so deep links like
`/projects/abc` work. HTTPS is required for installation to the home screen.

## 5. Turning on live AI

1. Create an API key in the Anthropic Console and set a monthly spend limit there.
2. `supabase secrets set ANTHROPIC_API_KEY=...` and redeploy the function.
3. Optional: `AI_MODEL` (default `claude-opus-5-5`), `AI_EFFORT`
   (`low`/`medium`/`high`, default `medium`), `AI_TIMEOUT_MS`.
4. Review the daily limits (`LIMIT_*_PER_DAY`) for your budget.
5. Open the app: the "Demo mode" labels disappear when `/config` reports
   live mode. Generate a few plans and check them before sharing the app.

The live path has been tested against a simulated client only (see
[KNOWN_LIMITATIONS.md](KNOWN_LIMITATIONS.md)), so step 5 is the first real
end-to-end check.

## 6. Checks

```bash
npm run typecheck   # TypeScript for the app + Deno check for the server
npm test            # 52 unit tests (validation, demo planner, progress, timer, API)
npm run test:e2e    # Flows A–E at 390px and 360px, plus accessibility checks
```

`test:e2e` starts its own API (port 8799, demo AI, test sign-in) and web
server (port 5199). Set `DENO_BIN` if `deno` is not on your PATH, and
`PW_CHROMIUM_PATH` to use an existing Chromium instead of `npx playwright install chromium`.

## 7. Demo-only preview build

For a shareable preview with no server (template plans, guest mode, data in
the browser only):

```bash
VITE_LOCAL_DEMO_AI=true VITE_AUTH_PROVIDER=none VITE_HASH_ROUTER=true \
  npx vite build --config vite.figma.config.ts --base ./
```

`dist/` then works from any static host or sub-path, because pages use
`#/path` URLs.
